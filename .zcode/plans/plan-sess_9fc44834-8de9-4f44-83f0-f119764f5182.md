## 第二部分：Filebeat 层「按字段丢弃」（服务 × 日志粒度）

**1. 数据模型**（沿用 000043 json 列先例，两侧同步）：
- `assets_application_service_log_setting` 加 `drop_conditions jsonb NOT NULL DEFAULT '{}'::jsonb`（MySQL `json DEFAULT (JSON_OBJECT())`）
- 迁移 `000049_service_log_drop_conditions.{up,down}.sql` 两方言、折叠快照 `db/schema/*/002_assets.sql`、`db/queries/*/assets.sql` 相关查询加列、`make derive/generate/facade`
- 条件模型复用 `{logic: all|any, conditions: [{field, op, value}]}`（行级作用域天然成立，不需要多条目）；空对象 = 不丢弃

**2. 编译与渲染**（`internal/logcollect/` 新纯函数 + 表驱动测试）：
- 条件编译为 Filebeat `drop_event.when`：eq→equals、ne→and(has_fields, not equals)、contains→contains、not_contains→and(has_fields, not contains)、empty→or(not has_fields, equals '')、not_empty→and(has_fields, not equals '')；logic=all→when.and、any→when.or——**全程不使用 regexp**
- 可用字段 = Filebeat 真实存在的：message、service（逻辑服务 code）、log_name、log_path、instance、host_ip（+ 自由输入 app_fields.* 等注入字段）
- `log_level` 做成**伪字段**（仅 eq/ne）：编译成对 message 的 JSON 字面量 regexp（`"log_level"\s*:\s*"<value>"`），UI 标注"JSON 日志可靠、文本日志请用 message 包含"
- 渲染点：`renderHostLogConfig` 中追加在 copy_fields 之后（log_path 已就位）；YAML 转义复用 yamlScalar；渲染输入查询（ListHostLogRenderEntries）带出该列
- 渲染产物变化 → 指纹变化 → 待下发 → 现有下发流程，无任何新增 ES 操作

**3. API 与校验**：
- 日志设置保存（单条 `settings/` + 批量 `settings/batch/`）接受 drop_conditions；保存时校验（字段名正则、操作符白名单、值必填性、条数 ≤10、logic 取值）；overridePayload 与响应带出

**4. 前端**（日志中心 `log-center/index.vue`）：
- 日志配置行新增「按字段丢弃」操作：弹窗 = 逻辑单选（满足全部/任一）+ 条件行增删（从 log-parsers 平移交互；字段建议 message/service/log_name/log_path + log_level 伪字段标注）+ 警示文案（"丢弃发生在采集端、不入库、不可恢复；改动需重新下发"）
- 行内摘要标识（已配置显示红色 tag）
- 本地试算：粘贴样例行，前端按同一映射逻辑显示保留/丢弃行数（采集过滤试算同款）
