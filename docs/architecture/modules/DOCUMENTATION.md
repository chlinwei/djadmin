# 文档中心

> **先从与系统菜单同名的模块进入，先看重点和流程图，需要底层细节时再展开“开发参考”。**

## 阅读流程

```mermaid
flowchart LR
    A["打开文档中心"] --> B["左侧选择菜单或搜索模块"]
    B --> C["先读重点与前置条件"]
    C --> D["查看可视化流程与失败分支"]
    D --> E["按本篇目录定位操作和排障"]
    E --> F["需要实现细节时打开开发参考"]
```

## 页面使用

- 左侧按产品菜单组织：资产管理、自动化运维、监控中心、安全中心、系统管理与个人中心。
- 登录认证与权限作为公共基础模块单列，不冒充真实业务菜单。
- 同一模块的多个菜单可跳到同篇手册的不同章节，避免每个页面复制一份重复说明。
- 正文上方提供本篇章节导航；点击目录、内部链接和章节不会新增多个系统标签页。
- 流程图使用 Mermaid，直接渲染为 SVG；不启用图中脚本或点击回调。语法或加载失败明确显示错误。
- 图片不自动加载外部资源；普通代码块保留源码显示。

## 内容边界

主目录只描述当前实现的操作与流程。**计划、历史记录和未上线功能不在系统阅读目录内发布**；
仓库保留它们用于维护追溯，不能将它们当作现成功能。
开发参考放实现模型、运行部署和公共约定，不与菜单手册争夺第一入口。

文档随前端构建发布，生产更新需重新构建发布前端。无后端文档文件服务、无数据库迁移。
所有已登录用户可见；静态资源不是机密存储，禁止放入密码、私钥或环境配置。

## 手册写作标准

1. 标题对应菜单/模块，开篇只突出最重要的结论与边界。
2. 写清入口、前置条件、正常流程、关键判断及失败路径。
3. 每个模块至少一张真实实现流程图；不能用未来设计冒充已实现链路。
4. 用表格突出状态差异、破坏性动作和常见误区，不写修复流水账。
5. 细节链接到技术参考；功能变化时同步维护流程图和说明。
