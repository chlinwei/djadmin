# 安全中心：基线扫描

> **这是操作系统配置合规扫描，不是漏洞/CVE 扫描，不自动修复配置，也不等于应用巡检。**

## 安全问题

**入口：安全中心 → 安全问题。** 新基线扫描的真实不符合结果按主机与稳定策略 ID 自动归并，
编辑规则不改变问题身份，内容版本和证据独立留痕；有效复查通过关闭，跨版本关闭标记为
“规则变更后通过”，不推断主机已修复；复发重开。Agent 离线、采集/求值错误或缺失结果
只能标记无法验证，不作为违规或通过。扫描详情单独展示执行异常，不计入不符合数量；
空断言或断言证据不一致也不能作为通过结论。
列表默认按风险聚合，可进入受影响主机问题及独立详情，查看分页发现/复查证据。
旧报告不回填，没有问题不等于资产已检查。页面要求独立 `security:issues:view`，
不提供人工整改状态、定期计划、账号盘点或自动修复。
完整状态机、并发与升级语义见[安全问题台账](../SECURITY_ISSUES.md)。

## 菜单入口与步骤

安全中心 → 基线扫描。先维护基线标准，再建立类目与策略，最后按项目/环境选择目标执行扫描。

1. 创建并启用基线标准。
2. 添加类目，编写 OPA 采集与断言策略，填写修复建议。
3. 默认“按主机”：不要求项目、环境，主机留空表示全部资产主机，也可多选部分主机。
   或切换“按项目”：选择项目及可选环境，扫描该范围内全部主机，不显示主机多选。
   切换扫描方式会清空旧主机选择；主机加载失败或范围为空不能提交。
   确认目标范围、Agent 在线状态后发起扫描，离线主机执行时会记录错误，不当作符合。
4. 查看逐主机、逐策略报告，对比预期值与实际值。

## 查看和编辑配置

基线、类目、策略分别复用自己的表单；`baseline:view` 可查看，同时拥有 `baseline:manage` 时显示编辑而不重复显示查看。打开已有记录时读取所选基线详情。策略表单保留所属基线/类目、严重级别、说明、运行用户、修复建议、所有采集行及完整 Rego 策略；策略保存按打开时的主键定位，不按列表下标定位。

只读表单不提供保存或增删采集行，不加载扫描和主机候选。扫描、排序、删除仍按原权限独立控制；扫描记录的执行报告保持独立。

## 扫描流程

```mermaid
flowchart TD
    A["选择基线"] --> M{"扫描方式"}
    M -->|按主机（默认）| N["全部资产主机 / 指定部分主机"]
    M -->|按项目| P["项目 / 项目×环境"]
    N --> B["解析主机并保存扫描记录"]
    P --> B
    B --> C["生成每主机检查计划与快照"]
    C --> D["经 gRPC 下发到 Agent"]
    D --> E{"采集与 OPA 求值是否成功？"}
    E -->|否| F["记录执行错误，不当作符合"]
    E -->|是| G["保存每条断言的预期与实际"]
    G --> H["汇总主机符合情况与符合率"]
    F --> I["展示扫描报告和错误明细"]
    H --> I
```

## 报告重点

- 策略配置引用的采集字段必须存在，保存时会校验。
- 不符合是规则结论，执行错误是输入或执行条件问题，处理方式不同。
- 类目和修复建议作为扫描快照保存；后来编辑基线不改写旧报告。
- 条目明细选择“通过”时隐藏“消息”和“修复建议”列，减少空白；切回“全部”或“不符合”时恢复，两列数据仍保留。
- 详情概要显示项目和具体环境清单；选择全项目扫描也列出涉及的环境，不只显示“全部环境”。
  按主机扫描概要显示“不限定项目、不限定环境”，不推断资产的项目归属。
  环境筛选同时过滤主机符合率和条目明细，多环境主机在对应环境均可查看但不重复计数。
  新扫描保存项目名称及逐主机环境快照；已有无快照记录按当前资产关联展示并显式标注，无法确认的归属显示“未记录环境”。
- 巡检与基线共享 OPA 内核，但使用独立的记录与聚合，不混表。
- 本模块不自动联动 Prometheus 告警，也不承诺已经有趋势、豁免或历史对比等规划能力。
