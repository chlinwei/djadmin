# 后台任务可靠性整改清单

> 状态：P0、P1 已实现，待真实环境复验。本清单不涉及 Trivy，不要求新增或拆分进程。

## P0：先消除任务丢失和漏触发

- [x] **P0-1：巡检、基线缺少可靠的执行接管。** 下发快照随任务和目标一起提交；单实例 API 重启时继续未领取目标，可能已下发的目标标记执行失败且结果未确认，不自动重发。详见[巡检架构](../architecture/INSPECTION_ARCHITECTURE.md)和[基线架构](../architecture/BASELINE_ARCHITECTURE.md)。
  - **验收：** 在落库后、下发前重启 API，任务能被重新接管；在下发后模拟中断，不重复执行结果未知的动作，也不留下永久运行中的任务。
- [x] **P0-2：定时巡检存在漏触发窗口。** [定时巡检](../../autoadmin/internal/inspection/scheduler.go)现在将计划推进和执行记录创建放进同一事务；同一「计划 ID + 应触发时间」只能成功领取一次。
  - **验收：** 模拟创建执行记录失败，计划不提前推进；重试或并发领取时，同一轮只创建一条执行记录。

## P1：补齐运行与部署边界

- [x] **P1-1：统一巡检、基线执行与定时循环的启停。** 由 API 进程入口管理；停机停止领取，按配置等待在途目标，未完成任务交给启动恢复。
  - **验收：** 停机期间不再领取新任务，进程在配置的期限内退出；重启后能对账未完成任务。
- [x] **P1-2：明确 API 与 Agent Gateway 的单实例约束。** [部署说明](../../autoadmin/deploy/README.md#api-instance-and-restart-boundary)明确禁止新旧实例重叠运行。多副本不在本期范围；未来引入时须先解决会话归属、下发路由及对账协调。
  - **验收：** 单实例约束在部署文档中明确；若支持多副本，任务进入非连接实例时能路由到会话归属实例，不把在线 Agent 误判为离线。

## 暂不整改

- 保留 `scheduler` 直接执行现有清理任务；不为分层新增消息投递。
- 保留 `worker` 的自动化失联作业对账职责；不把已有后台任务强行迁入。
- 不先拆独立 Agent Gateway；优先解决任务可靠性，并在确有独立扩容或故障隔离需求时再评估。
